# Asset manager motivation audit

Audited November 17, 2026 against LoA `731f3742ccb5` and the changes accompanying issue #52. Server evidence is from `drivecore/landofassets` at `6e40f328f8db13675285e5a615db023d8f529464`. This is a source and functional audit, not a production SLA, browser rendering benchmark, or validation of personal history.

## Local development contract

Keep the published selection in the tracked manifest and lockfile, using a short alias:

```json
{ "name": "showroom", "assets": { "chair": "acme/models/chair@1.0.0" } }
```

App code always loads `loa:chair`. To experiment, put this in the gitignored workspace-root `assets.local.json`:

```json
{ "overrides": { "chair": "file:./drafts/chair.glb" } }
```

Precedence is **local override → installed project file → remote URL** in auto mode. Paths are relative to the workspace root, including when overriding an alias declared in a child workspace. Unknown aliases, missing draft files, and non-file overrides fail explicitly. Overrides never rewrite the manifest or lockfile. `install` continues to install the tracked selections so removing a draft can return to them. Publish a draft and update the manifest when ready to share it.

Do not edit an installed native file as a development workflow: it remains read-only and integrity-checked. Clone/copy isolation means an intentional chmod/edit can no longer corrupt the shared store, but the runtime will reject those edited native bytes. A hard link or symbolic link cannot provide that isolation. pnpm likewise documents [clone-based edit isolation and import methods](https://github.com/pnpm/pnpm.io/blob/main/versioned_docs/version-10.x/settings.md). Hash store keys also deduplicate identical bytes published under different names/versions, and directly match locked integrity and download URLs; replacing them with scoped-version keys would lose those properties without improving the loader UX.

## Large-project measurements

The local Three.js `landofassets-examples` branch at `4e321eee6eca` contains direct versioned media URLs, not an asset-manager manifest. Extracting its literal native references yielded **97 unique assets, 135,189,850 bytes (135.2 MB / 128.9 MiB)**. Dynamic URL expressions were not expanded. Every literal reference resolved against production. This approximates the requested 150 MB case rather than asserting that branch already uses CLI installs.

The [fixture manifest](benchmarks/three-examples-assets.json) and [lockfile](benchmarks/three-examples-assets-lock.json) contain only references, not binaries. The [benchmark runner](../scripts/benchmark-assets.mjs) copies them into isolated temporary projects with a private temporary store. It runs real CLI installs sequentially, waits for process completion, includes startup/integrity checks/materialization, and removes the temporary store. Warm runs reuse the store and the OS file cache. No rendering or GPU work is measured.

On this Mac (Darwin 27.2.0 arm64, Node 26.3.0), wall-clock seconds including CLI startup:

| Concurrency          | Empty store/project | Warm reinstall median (3 runs) | New project, warm store median (3 runs) |
| -------------------- | ------------------: | -----------------------------: | --------------------------------------: |
| 4 (previous default) |              48.207 |                          0.568 |                                   0.488 |
| 8                    |              25.834 |                          0.528 |                                   0.557 |

All cold runs downloaded 128.9 MiB; all warm runs reported zero downloads and clean redirected output. Cold timings are individual production-network observations, not a controlled CDN throughput guarantee. Sixteen downloads improved this sample further but with diminishing returns; eight is the conservative default. Increasing concurrency to eight reduced the observed cold-install time, while retaining a bounded streaming workload. The default is now eight; `--parallel` remains configurable. Raw samples: [4 downloads](benchmarks/three-examples-results.json), [8 downloads](benchmarks/three-examples-results-8.json), [16 downloads](benchmarks/three-examples-results-16.json).

To reproduce after building, copy the fixture files into a temporary directory as `assets.json` and `assets-lock.json`, then run:

```sh
pnpm install --frozen-lockfile
pnpm build
node scripts/benchmark-assets.mjs /path/to/fixture 8
```

The runner downloads public production originals and deletes its isolated cache afterward. It does not use or prune your usual store. Disk allocation savings depend on clone support; these timings alone do not prove an exact physical storage ratio.

A production HEAD check of `robotexpressive@1.0.0` also confirmed HTTP 302 with `public, max-age=60` at the API URL, followed by HTTP 200 from `content.threeify.com` with `public, max-age=31536000, immutable`.

## Validation and adoption

Regression tests cover clone-unavailable cache isolation after edits/deletion, shared-hash concurrent download deduplication, clean non-interactive install output, CLI override resolution, workspace-relative overrides, unknown and missing override inputs, mixed local/remote builds, native integrity errors, and live Vite source transitions. Existing CLI tests also verify warm offline reuse and corruption repair.

The Vite default changes from `remote` to `auto`. Set `loa({ mode: 'remote' })` explicitly to retain remote selection when installed native or URL files are present. Overrides are intentional local substitutions in every mode and may be bundled into a build; CI should build from the committed inputs without a local override file. This audit does not add an asset approval system or optimized-variant selection to the asset manager.

Local checks passed: frozen dependency installation, build, typecheck, lint (existing warnings), formatting, all 395 tests, and package-content checks. The extra `pnpm docs:build` check fails during Docusaurus server rendering with `SyntaxError: Invalid left-hand side in assignment` at a generated `"release" = namespaces` statement in bundled dependency code. A separate clean worktree at unchanged `origin/main` reproduces the same failure. No website tooling/dependency changes are included here.
